SampledSpline

A static copy of a spline as straight segments between samples along it, made by Splynx.sampled. Finding the segment for a distance takes a single division and a table read instead of a search, which makes it the fastest spline for distance lookups.

Between samples it's a straight line, so it's off by about spacing^2 / (8 * radius) on a bend of that radius. Sharp corners get cut across by up to half the spacing, unless it keeps the joints, which puts a sample on every corner.

It only knows distances, so alpha is always a fraction of the length: SampledSpline:getPos moves at a constant speed.

Types​

Segments​

</>
interface Segments {
points: {vector}--

The samples, relative to the pivot. There's one more than there are segments.

directions: {vector}--

Each segment's direction, as a unit vector. Segments with no length borrow a neighbour's.

distances: {number}--

How far along the spline each sample is.

count: number--

The number of segments.

}

A sampled spline's own data, frozen so it can be shared instead of copied. See SampledSpline:getSegments.

getOffsetPosAtDistance​

</>
SampledSpline:getOffsetPosAtDistance(
distance: number,--

Studs from the start. Clamped to the length.

offset: number,--

Studs to the right of the direction of travel; negative is to the left.

hint: number?--

Ignored: there's no search to speed up. Accepted so calls match the other splines.

) → (
vector,--

The offset position.

vector,--

The spline's direction of travel there, as in SampledSpline:getDirectionAtDistance.

number--

The segment index, in place of a hint.

)

The position offset studs to the side of the spline, distance studs along it, for things that walk beside the path instead of on it. The side is horizontal, so the height stays the spline's. Straight up or down has no horizontal side, so there it keeps the side of the nearest part of the spline that isn't vertical: a climb that bends up and over in one vertical plane keeps the same side the whole way.

Offset positions jump a little at each sample where the direction changes, by about offset * angle. Smaller spacing makes the jumps smaller.

getSegments​

</>
SampledSpline:getSegments() → Segments

The samples, segment directions and distances the spline is made of, for building your own lookups on top of it. They're the spline's own lists, frozen rather than copied, so this costs nothing. Points are relative to the pivot. 

local segments = sampled:getSegments()
local pivot = sampled:getPivot()
for i = 1, segments.count do
    local from = pivot + segments.points[i]
    local direction = segments.directions[i]
    local length = segments.distances[i + 1] - segments.distances[i]
end
