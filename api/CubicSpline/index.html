CubicSpline

Smooth curves, made by Splynx.bezier, Splynx.hermite, Splynx.cardinal, Splynx.catmullRom, Splynx.bSpline, Splynx.rounded and Splynx.filleted. Every type is stored the same way, as one cubic polynomial per curve, so they all cost the same to query; they only differ in how points become curves.

Distance lookups use a table per curve that maps evenly spaced distances to alphas. It's built the first time a distance lookup or CubicSpline:getLength needs it, and rebuilt for the curves an edit changes, so an edit followed by a distance lookup costs a few microseconds. Positions are within about 0.0005 studs of the true distance.

Functions​

getPos​

</>
CubicSpline:getPos(
alpha: number--

From 0 (the start) to 1 (the end). Clamped.

) → vector

The position at alpha. Alpha splits evenly across curves, so with 4 curves, 0.25 is the end of the first. Since curves have different lengths, equal alpha steps don't move at a constant speed; use CubicSpline:getUniformPos or CubicSpline:getPosAtDistance for that.

getPosAtDistance​

</>
CubicSpline:getPosAtDistance(
distance: number,--

Studs from the start. Clamped to the length.

hint: number?--

The hint returned by the previous lookup on this spline, if any.

) → (
vector,
number--

A hint for the next lookup.

)

The position distance studs along the spline. This is the call to use for things moving at a constant speed: keep a distance, add speed * deltaTime to it every frame, and pass back the hint from the last call. 

local distance, hint = 0, nil
RunService.Heartbeat:Connect(function(deltaTime)
    distance = (distance + speed * deltaTime) % spline:getLength()
    local position
    position, hint = spline:getPosAtDistance(distance, hint)
end)

getOffsetPosAtDistance​

</>
CubicSpline:getOffsetPosAtDistance(
distance: number,--

Studs from the start. Clamped to the length.

offset: number,--

Studs to the right of the direction of travel; negative is to the left.

hint: number?--

The hint returned by the previous lookup on this spline, if any.

) → (
vector,--

The offset position.

vector,--

The spline's direction of travel there, as in CubicSpline:getDirectionAtDistance.

number--

A hint for the next lookup.

)

The position offset studs to the side of the spline, distance studs along it, for things that walk beside the path instead of on it. The side is horizontal, so the height stays the spline's. Straight up or down has no horizontal side, so there it keeps the side of the nearest part of the spline that isn't vertical: a climb that bends up and over in one vertical plane keeps the same side the whole way.

Offset positions jump at sharp corners, where the side flips from one line's to the next. On a rounded corner they move smoothly as long as the offset is smaller than the arc's radius. For Splynx.rounded that's reach / tan(turn / 2): the reach at a right angle, and less for sharper turns.

Errors

TypeDescription
"Spline doesn't have enough points to make a curve"If the spline has no curves.

getPosAtDistances​

</>
CubicSpline:getPosAtDistances(
distances: {number},--

Studs from the start, one per lookup. Clamped to the length.

outPositions: {vector},--

Filled with the position for each distance.

outDirections: {vector}?,--

Filled with the direction of travel for each distance.

offsets: {number}?,--

One per distance: studs to the right, as in CubicSpline:getOffsetPosAtDistance.

hints: {number}?--

One per distance, read and then replaced with the hint for the next call.

) → ()

Many lookups in one call, written into lists you keep, so nothing new is made. Meant for many things moving along the same spline: keep their distances (and offsets) in lists, and pass the same hints list every frame. 

local distances, positions, directions, hints = {}, {}, {}, {}
RunService.Heartbeat:Connect(function(deltaTime)
    for i, distance in distances do
        distances[i] = distance + speed * deltaTime
    end
    spline:getPosAtDistances(distances, positions, directions, nil, hints)
end)
